# 七大奇迹对决（7 Wonders Duel）

基础版《七大奇迹对决》的浏览器实现。含**本地热座**、**人机对战**（三档难度）、**联机对战**。
规则引擎是纯函数模块，三种模式共用同一套动作协议与状态结构。

## 快速开始

```bash
cd 7-Wonders-Duel-game
npm install
npm run dev        # 单机模式：http://localhost:5173
```

## 三种玩法

| 模式 | 怎么开始 | 说明 |
|---|---|---|
| 本地热座 | 顶栏切「本地热座」 | 两人轮流用同一台设备 |
| 人机对战 | 顶栏切「人机对战」，选难度 | 你是玩家一，AI 执玩家二 |
| 联机对战 | 顶栏切「联机对战」 | 见下方 |

## 联机对战

### 推荐方式：一台电脑当服务器

```bash
npm run build      # 先构建前端
npm run server     # 启动服务器（默认端口 8080）
```

启动后会打印类似：

```
  本机访问：    http://localhost:8080
  局域网访问：  http://192.168.5.4:8080   <- 同一 WiFi 下的另一台设备用这个
```

然后：

1. 这台电脑（或同一 WiFi 下的手机 / 平板）打开上面任一地址
2. 一台点「创建房间」，得到 6 位房间码
3. 另一台输入房间码加入
4. 双方点「我准备好了」，房主点「开始对局」

服务器**同时托管网页和对局**，不需要另配 Web 服务器，也不需要连公网。
换端口用 `PORT=9000 npm run server`。

### 用 Vite 开发服务器时另外连

若前端是 `npm run dev`（5173）单独跑的，在地址后加 `?srv=` 指向联机服务器：

```
http://localhost:5173/?srv=ws://192.168.5.4:8080
```

### 手机能当服务器吗

**能，但不推荐。** 技术上 Node 可以在 Android（Termux）上跑，但会遇到权限、后台被杀、
端口与热点隔离等一堆麻烦事。**更省事的做法是：手机当客户端，电脑当服务器**——
手机只要打开电脑打印的那个局域网地址即可，不需要装任何东西。

## 联机的关键设计

- **服务器权威**：只有服务器执行 `applyAction`，客户端只发意图。
- **只下发公开状态**：`publicView()` 会剥掉 `seed`、`rngState`、未翻开的暗牌、
  开局被移出的牌与大图书馆的抽取池。有了 seed + 完整日志就能反推暗牌，所以 seed 绝不下发。
- **本作没有个人手牌**：暗牌对双方都不可见，因此只广播**一份**公开状态，不必按座位裁剪。
- **断线重连**：按 `clientId` 回到原座位，60 秒内重连可继续；超过 90 秒判负。
- **先后手平衡**：房间内「再来一局」会自动交换座位。

## 校验脚本

| 命令 | 作用 |
|---|---|
| `npm run check` | 三时代牌阵拓扑、卡表数量、连锁闭合性、科技符号分布 |
| `npm run sim 300` | 随机策略跑 N 局，验证无死锁、奇迹上限、金币非负等不变量 |
| `npm run smoke` | 首屏 / 中局 / 终局 / 联机大厅各状态的渲染冒烟 |
| `npm run bench 14` | AI 三档难度的胜率与耗时基准 |
| `npm run proto 40` | 联机端到端：起真实服务器 + 两个真实客户端跑完整对局 |

## 目录结构

```
src/
├── core/                规则引擎（纯函数，不依赖 React / 网络）
│   ├── data/            卡牌 73 张、奇迹 12、发展标记 10、牌阵 ASCII 拓扑、军事轨道
│   ├── layout.ts        牌阵解析与「可拿取」判定
│   ├── resources.ts     资源产出、贸易定价、建造费用方案
│   ├── engine.ts        setup / 合法动作 / applyAction / 胜负判定
│   ├── scoring.ts       终局计分与行会 vpPer 结算
│   ├── visibility.ts    状态脱敏（联机下发与本地渲染共用）
│   ├── rng.ts           可复现随机流（mulberry32）
│   └── types.ts         领域类型
├── ai/                  评估函数 + Alpha-Beta 搜索 + 隐藏信息确定化采样
├── ui/
│   ├── sources/         对战源适配层（LocalSource / OnlineSource）
│   ├── components/      牌阵、城市面板、军事轨道、房间面板、弹窗
│   ├── audio.ts         Web Audio 程序化音效
│   └── App.tsx
server/                  联机服务器（原生 Node 实现的 WebSocket，无第三方依赖）
scripts/                 校验与基准脚本
```

## 已实现的规则

- 三时代轮抽、牌阵明暗牌与「不被压住才可拿取」
- 资源产出与贸易定价（2 + 对手棕/灰卡同资源符号数，商业卡可压到 1 金）
- 连锁免费建造、金币费用、费用减免（建筑学 / 石工术）
- 建造建筑、弃牌换金（2 + 黄卡数）、建造奇迹（全场上限 7 座，第 7 座落成后剩余一张移出游戏）
- 军事：冲突标记、区块罚金（2 / 5 金币）、军事压制胜利
- 科技：7 种符号、成对得发展标记、集齐 6 种即科技压制胜利
- 10 枚发展标记全部生效；12 座奇迹效果全部生效
- 时代交接由军事较弱方决定先手；平局由最后行动者决定
- 终局计分（军事 / 建筑 / 奇迹 / 发展 / 金币），平局比市政分
